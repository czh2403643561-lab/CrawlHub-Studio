# 商品榜单页面 UI 方案

## 问题总结

当前页面把六个榜单合并成一张商品表，并在同一行堆叠多个榜单标签，导致以下问题：

- 用户无法快速判断当前浏览的是哪个榜单
- 同一商品在不同榜单中的排名和指标语义被混在一起
- 所有字段被压进同一套列，榜单专属内容没有合适位置
- 榜单来源标签占用横向空间，降低商品名称和核心指标的可读性

统一商品库可以继续用于本地去重和关联，但主页面必须按榜单来源分开展示。“汇总/去重视图”不进入本阶段主界面。

## 设计目标

- 默认进入“总榜”，一次只展示一个榜单的数据
- 六个榜单使用固定 Tab 切换，位置和顺序保持稳定
- 保留 TikTok 榜单的高信息密度，同时适配 CrawlHub Studio 的桌面工作台结构
- 商品封面、名称、价格、评分集中展示，减少独立列数量
- 根据榜单内容切换专属列，不强行共用一套表头
- 在常见桌面宽度下展示完整关键字段，不出现横向滚动
- 导入功能保持可见但弱化，不抢占榜单浏览区域

## 页面主结构

页面从上到下分为五个区域：

1. **顶部信息区**
   - 标题：`TikTok 热卖商品榜`
   - 简短说明：当前榜单用途
   - 右侧显示数据时间、当前分类和本地保存状态
   - 没有可靠时间数据时显示“数据时间未提供”，不制作无效日期控件

2. **导入按钮区**
   - 放在顶部信息区右侧或其下一行右侧
   - 保留“选择 JSON 文件”“选择六榜文件夹”“导入并保存”三个操作
   - 默认只显示按钮和一行简短状态；文件明细、校验结果仅在选择文件后展开

3. **榜单切换区**
   - 固定顺序：总榜、直播榜、短视频榜、商品卡、达人榜、新品榜
   - 当前 Tab 使用品牌色下划线和较深文字，不使用大面积色块
   - Tab 可显示当前榜单商品数，例如 `总榜 10`

4. **筛选区**
   - 紧贴 Tab 下方，保持单行紧凑布局
   - 第一阶段建议预留：分类、商品关键词、GMV 下限、收藏状态
   - 下方显示一条浅色榜单说明，例如“直播榜按直播渠道产生的 GMV 排名”
   - 筛选条件只作用于当前 Tab，不跨榜单混合结果

5. **列表区**
   - 表头固定、行高约 76–88px、商品图约 44px
   - 商品名称最多两行，价格、评分和评价数放在商品单元格内
   - 操作列保持窄列，只保留“查看”“收藏”
   - 空值统一显示 `—`，不显示 `0` 代替未知数据

建议结构：

```text
页面标题与数据状态                         [选择 JSON] [选择六榜文件夹] [导入并保存]
总榜 | 直播榜 | 短视频榜 | 商品卡 | 达人榜 | 新品榜
[分类] [搜索商品] [GMV 下限] [收藏状态]
[当前榜单说明]
┌排名┬商品信息────────┬榜单专属内容────┬核心指标────┬操作┐
│    │封面/名称/价格/评分│视频、达人或直播账号│GMV/点击/CTR │    │
└────┴────────────────┴────────────────┴────────────┴────┘
```

## 榜单切换交互

- 首次打开默认选中“总榜”
- 点击 Tab 后，只读取并展示该 `rank_type` 对应的榜单记录
- 排名、排名变化和指标必须来自当前榜单来源，不能沿用其他榜单的数据
- 当前筛选条件在切换 Tab 时重置，避免用户误以为榜单缺少数据
- 当前 Tab 没有数据时展示空状态和导入入口，不回退到其他榜单数据
- 同一商品属于多个榜单时，在每个相关 Tab 中分别出现，并显示该榜单自己的排名与指标
- 暂不提供“全部榜单”Tab；未来如增加汇总视图，应独立命名为“汇总”，且不作为默认页

## 列表通用设计

所有榜单共享以下基础结构：

- **排名**：名次与升降变化合并为一个窄列；前三名使用轻量图标或颜色
- **商品**：缩略图、商品名称、价格、评分、评价数；店铺名可放在次要信息行
- **核心指标**：数值区间保持原始文本，数字右对齐
- **操作**：查看、收藏

桌面宽度分配建议：排名 7%–9%、商品 32%–38%、榜单专属列 22%–30%、指标 18%–25%、操作 8%–10%。优先减少次要字段，而不是压缩到横向滚动。

## 六榜字段与列表方案

### 总榜

`排名/变化 | 商品 | GMV | 点击量 | CTR | 操作`

- 商品单元格：封面、名称、价格、评分、评价数、店铺
- 用途：查看平台整体热卖表现，保留最完整的通用转化指标

### 直播榜

`排名/变化 | 商品 | 直播账号 | GMV | 操作`

- 直播账号列：账号头像（有数据时）、账号名称、账号 ID
- 商品单元格继续显示价格、评分、店铺
- 点击量和 CTR 不作为主列，避免挤占直播账号空间；详情中仍可查看

### 短视频榜

`排名/变化 | 商品 | 表现最佳视频 | GMV | 操作`

- 视频列展示最多 4 个小封面，额外数量显示 `+N`
- 无视频封面时显示统一占位，不使用空白区域
- 视频创作者信息可在悬停或详情中查看，不额外增加主列

### 商品卡

`排名/变化 | 商品 | GMV | 点击量 | CTR | 操作`

- 结构接近总榜，但榜单说明明确为商品卡渠道
- 来源没有排名时显示 `—`，不自动补排名
- 保留点击量和 CTR，便于判断商品卡曝光后的转化表现

### 达人榜

`排名/变化 | 商品 | 带货达人 | GMV | 操作`

- 达人列展示最多 4 个头像，额外数量显示 `+N`
- 只有达人数量、没有头像时显示“共 N 位达人”
- 单一主要达人可显示名称；详细达人清单留在商品详情

### 新品榜

`排名/变化 | 商品 | GMV | 点击量 | CTR | 操作`

- 榜单说明突出“最近 30 天上架”口径
- 商品单元格可增加轻量“新品”标记，但不新增独立列
- 保留通用转化指标，便于评估新品起量速度

## 导入区布局

- 三个按钮与页面标题同行靠右，整体高度控制在一行
- “导入并保存”作为主按钮，两个选择入口使用次级按钮
- 未选择文件时不展示大面积说明卡，只显示“尚未选择文件”
- 选择后在按钮下方展开一条状态：文件数、识别榜单数、商品记录数和校验结果
- 导入成功后状态自动收起为“六榜已更新 · 共 N 条 · 时间”
- 导入错误只展开当前错误，不改变 Tab 和现有列表内容

## 数据展示前提

当前统一商品库已经保存多榜来源，但商品的 GMV、点击量、CTR、视频和达人信息需要按榜单来源分别保留。正式实现 Tab 前，应先确保每条榜单记录都保存自己的指标和专属字段，否则切换榜单时可能显示其他榜单最后写入的数值。

建议的单条榜单记录范围：

`rank_type、rank、rankChange、gmv、clicks、ctr、video、creator、liveAccount、sourceFile、importedAt`

该调整只服务六榜正确展示，不改变统一商品去重关系。

## 建议实现顺序

1. 补齐榜单来源记录中的独立指标和专属字段，并兼容现有本地数据
2. 增加六个固定 Tab，默认总榜，完成按 `rank_type` 切换
3. 建立共用商品单元格和榜单独立表头配置
4. 分别实现直播账号、视频封面、达人头像三类专属单元格
5. 将导入区压缩到顶部，并保留现有校验反馈
6. 接入当前 Tab 范围内的基础筛选，最后检查常见桌面宽度无横向滚动

本方案确认后再进入正式页面重构。
